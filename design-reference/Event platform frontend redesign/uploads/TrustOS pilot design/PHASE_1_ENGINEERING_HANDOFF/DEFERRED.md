# Intentionally Deferred

These are **good ideas removed from Phase 1 on purpose** — to keep the pilot small, honest and shippable tonight. Nothing here is cancelled; each has a "revisit when" trigger. Do not build these now.

## Screens / areas deferred
| Item | Priority | Revisit when |
|---|---|---|
| Admin console — advanced (beyond the simple overview, which is now **P0**) | P2 | Second vendor onboards |
| Advanced / business analytics | P2 | A vendor asks "how am I doing?" with real volume |
| Templates (quotes, packages, checklists) | P2 | Same job type has run 3+ times |
| Team member / second-shooter screens | P2 | A project needs a second person |
| Venue intelligence / research pages | P2 | Post-pilot |
| Notifications centre | P1 | More than ~5 live projects per vendor |
| Advanced customisation (branding, theming) | P2 | Vendor #2+ needs own identity |
| Clients — rich CRM (basic Clients page is now **P0**) | P1 | Vendor has >10 clients |
| Settings (beyond profile + payments) | P1 | After first pilot week |
| Preparation — templated/advanced (basic Preparation is now **P0**) | P1 | First shoot-day dry run |
| Pay-securely-online (Stripe) | P1 | A client asks to pay by card |
| Quote builder (rich editor) | P1 | Manual quote proves too slow |
| Client approval / review workflow | P1 | First delivery goes out |

## Visual / interaction ideas deferred
- Optional/decorative animation (parallax, floaty cards, glow sweeps) — Phase 1 keeps only screen fade-in + skeleton shimmer.
- Secondary concept screens and alternate layouts from earlier explorations.
- Journey stepper tap-to-jump (read-only in Phase 1).
- Editing completed Event Details inline.
- Rich media in messages (attachments, read receipts).
- Dark mode for the vendor canvas (the rail is dark; the canvas stays warm).
- Multi-currency / tax handling in Money.
- In-app search results page (the field is present; wiring is P1).

## Still outside P0 (explicitly held back)
Stripe / pay-securely-online · Templates · Team access · advanced analytics · automation. These stay deferred; the pilot runs on manual/free payments and the P0 loop only.

## Why this restraint is the point
The pilot tests whether TrustOS genuinely improves how MiniMomentz runs one real project — not whether it can look like a mature SaaS. Every deferred item would add surface area to learn from before we know the core loop (setup → Event Details → quote → payment → prep → delivery → approval) actually feels calmer. Ship the loop; earn the rest.
